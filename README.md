# おしりーす

推し活用品レンタルサービスのコンテスト提出用アプリです。

ライブやイベントで使用する用品を、必要な期間だけ借りるサービスを提案しています。スマートフォン向けの画面を基本に、PCのブラウザにも対応しています。

## 主な機能

- メールアドレス・パスワードによる会員登録、ログイン、パスワード再設定
- アーティスト・商品カテゴリ・キーワードによる商品検索
- ペンライト、バッグ、双眼鏡、ファンサうちわセット、推し活セットの商品詳細
- 商品ごとのカラー・種類・数量・レンタル日程の選択とカート
- 初回注文時の会員情報登録、注文確認、注文番号付きのレンタル履歴
- 日別・種類別の在庫確認、注文に応じた在庫確保、キャンセル・延長
- お気に入り、最近見た商品、持ち物チェックリスト、空き待ちリスト
- 推しカラーに合わせた画面の配色変更
- イベント予定の登録、カウントダウン、節目の日の全画面お知らせ
- 商品別レビューの投稿・表示
- お問い合わせ、管理者からの返信、利用者への通知
- 管理者による商品・在庫・レンタル申込・空き待ち・お問い合わせの管理

## 使用技術とデモの範囲

- HTML、Sass、JavaScript（フレームワークなし）
- Firebase Authentication：認証
- Cloud Firestore：商品・利用者情報・注文・在庫などの保存
- Node.js / npm：ローカルサーバー、Sassのビルド、公開用ファイルの作成、テスト
- ZipCloud API：郵便番号からの住所検索

実際の決済・商品の発送は行わないデモです。デモのアーティストは架空のグループです。レビューにはサンプル5件を含みます。

持ち物チェックリストや最近見た商品など、端末内に保存する情報もあります。すべての機能が別端末へ同期するわけではありません。カウントダウンのお知らせはアプリを開いた際の表示で、アプリを閉じている間のプッシュ通知ではありません。

## 開発

```sh
npm ci
npm run dev
```

開発サーバーは `http://localhost:4173` です。同じポートで起動済みの場合は、既存のサーバーを使用してください。

Node.jsとnpmを使用できる環境で、プロジェクトのルートフォルダから実行してください。ブラウザで `index.html` にアクセスすると、ログイン画面へ移動します。HTMLを直接ダブルクリックして開くのではなく、ローカルサーバーまたは公開サーバーを使用します。

```sh
npm run build
npm test
```

CSSは `src/scss/` のSassから生成します。`style.css` を直接編集せず、生成後の差分も確認してください。

整形は `npm run format`、整形状態の確認は `npm run format:check` で実行できます。整形コマンドは複数のファイルを対象にするため、共同作業中は差分を確認してください。

## 構成

- ルートのHTML: 利用者画面と管理者画面
- `assets/js/`: ページの処理、Firebaseとの通信、初期化処理
- `assets/images/`: 表示用画像とアイコン
- `src/scss/style.scss`: 共通スタイルと各部分の読み込み
- `src/scss/_*.scss`: 商品詳細・管理・カウントダウンなどのスタイル
- `tests/`: 保存処理、在庫、画面構造、参照ファイルのテスト
- `scripts/`: 開発サーバーと公開用ファイル作成の処理
- `dist/`: 公開用の生成物（Gitの管理対象外）

## 公開用ファイル

```sh
npm run release
```

CSSをビルドして、公開に必要なHTML・JavaScript・画像・CSSだけを `dist/` に集めます。Cyberduckでは **`dist` の中身**をサーバーの公開フォルダへアップロードしてください。既存の相対パスを保つため、`src/scss/style.css` の配置も維持します。

現在の公開先がサーバー上の `33app/` なら、その中へ `dist/` 内のHTML・`assets/`・`src/` をアップロードします。`dist/` フォルダ自体を入れる必要はありません。同名ファイルは最新のものに更新します。サーバー側で直接編集した内容がある場合は、先に手元の元ファイルへ反映してください。

元のHTML・`assets/`・`src/` が編集用で、`dist/` はその公開用コピーです。同名ファイルが2か所にあるのは、この役割の違いによるものです。サーバー側を整理しても、手元の開発用ファイルは削除しません。

`node_modules`、テスト、Sassの元ファイル、Gitの履歴、Firebaseルール・インデックス設定、初期登録用の `firebase_seed.html` / `firebase_seed.js` は公開用フォルダに含めません。FirestoreルールはFirebaseコンソールで別途公開します。

`dist/` は生成物です。修正は元ファイルに行い、再度 `npm run release` を実行してください。このコマンドが作った `dist/` は再実行で作り直します。

ページ別のJavaScriptとSassは、担当箇所と読み込み順を明確にするため分割したまま管理します。最終的に配信するCSSは、従来どおり `style.css` 1つです。

公開先では `npm run dev` を実行する必要はありません。HTTPSの公開URLから、ログイン・商品表示・注文・管理者画面・お問い合わせ・レビューなどの動作を確認してください。アプリのファイル更新とFirestoreルールの公開は別の操作です。

## Firebase

`assets/js/firebase_config.js` のプロジェクトを使用します。ルールを変更した場合は、`firestore.rules` の内容をFirebaseコンソールで公開してください。

`firebase_seed.html` は管理者による商品初期登録用です。通常の画面からリンクしていませんが、セットアップに使用するため残しています。

管理者画面の入口は `admin_login.html` です。Firebase Authenticationのアカウントと、その利用者のUIDに対応する `admins/{uid}` ドキュメントで権限を確認します。一般の利用者登録だけでは管理者にはなりません。ログイン情報はREADMEに記載しません。

会員情報、お気に入り、カート、ライブ予定は利用者ごとに保存します。カウントダウンは `users/{uid}/countdown/current`、お問い合わせは `contacts`、返信通知は `notifications` を使用します。

商品は `products`、種類別在庫はその下の `variants`、注文は `orders`、日別の在庫確保情報は `inventoryDays`、空き待ちは `waitlists` を使用します。

レビューは `reviews/{送信ID}` に利用者ID・商品ID・評価（1〜5）・本文（300文字以内）・公開状態・投稿日時を保存します。商品詳細から `review.html?id=商品ID` に移動し、同じ商品の公開投稿だけを表示します。HTMLのデモ5件は残し、件数・平均はデモ5件とクラウド投稿から計算します。以前の端末共通のレビューは投稿者・商品を特定できないため自動移行しません。更新した `firestore.rules` をFirebaseコンソールで公開してください。

ライブの1ヶ月前・7日前・3日前・前日・当日は、起動時に全画面のお知らせを表示します。表示済みの日付は利用者ドキュメントの `countdownReminderDate` に保存し、同じアカウントではその日の再ログインや別端末で重複表示しません。日付は日本時間で判定し、1ヶ月前は前月の同日（月末はその月の最終日）です。アプリを閉じている間に届くプッシュ通知ではありません。

お知らせはイベント名・残り日数をグラデーションの円に表示し、背後をぼかします。残り日数ごとに案内文を変え、当日はクラッカーと花びらの演出を一度再生します（動きを減らす設定では演出を省略）。イベント当日が有効な注文のレンタル期間内なら持ち物チェックリストへ、注文がない場合は7日前以降にレンタルへ案内します。注文を取得できない場合は未注文と決めつけず、予定確認へのリンクを表示します。

カウントダウン画面のカレンダーアイコンから予定を追加します。登録済みの予定は、予定カードの下にある「この予定を編集する」から変更できます。

## 互換性と素材

- 商品詳細は `product_detail.html?id=商品ID` に統一しています。
- 旧 `set.html` は `product_detail.html?id=set` への転送専用です。
- Firebaseに画像パスが保存されている場合があるため、商品画像はコードからの参照だけで削除しないでください。
- `lucide_license.txt` と画像生成プロンプトは、素材のライセンス・制作記録として残しています。

変更したら、ビルド・テストの後にログイン、商品選択、注文、管理画面の主要な導線も確認してください。自動テストのFirebase処理はモックであり、公開済みルールと実際の端末間同期は別途確認が必要です。
